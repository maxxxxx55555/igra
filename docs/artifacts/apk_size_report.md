# APK size report — texture compression (STEP 7, RELEASE CONVERGENCE, 2026-09-12)

Measured, not guessed: every number in §1-2 comes from a command run against the
committed tree + this machine's local `.import` cache (gitignored, regenerated by
`godot --headless --path . --import`) on 2026-09-12. No texture's compression
mode was changed this pass — see §4 for why, and the concrete owner steps.

## 1. Baseline (measured)

- **738 texture source files** (`.png`/`.jpg`) under `assets/`, **738 matching
  `.import` files** (1:1, no orphans).
- **41.2 MiB** total on-disk source size (`find assets -iname '*.png' -o -iname
  '*.jpg' | du -cb` → 43,187,390 bytes).
- **100% `compress/mode=0` (Lossless), 0% VRAM Compressed** — verified by
  grepping every texture `.import` file's `[params]` block, no exceptions.
- `export_presets.cfg`'s Android preset already has `texture_format/etc2_astc=
  true` set (from an earlier pass) — inert today since nothing is VRAM
  Compressed yet, correct and ready for whenever this migration lands.

(An earlier pass's `docs/KNOWN_ISSUES.md` entry cites "1230" textures; this
pass's fresh, narrower count is 738 — likely counting only `.png`/`.jpg` under
`assets/` versus a broader glob or a different snapshot in time. Both agree on
the finding that matters: **100% Lossless, 0% VRAM Compressed.**)

## 3. Estimated impact — honest range, not a promise

**VRAM/runtime memory (the real, reliable win):** ETC2/ASTC block compression
is textbook 4-6x smaller than uncompressed RGBA8 in GPU memory for RGB
content, somewhat less (roughly 3-4x) for textures with an alpha channel,
because block formats are typically fixed-rate (fixed bits/pixel) rather than
detail-dependent. This matters most on low-end Android devices where texture
memory pressure causes stutter/eviction, not on this dev machine's own specs.

**APK/download size (less certain for THIS game specifically):** Lossless PNG
already compresses very well on flat, gradient, palette-locked art — exactly
this game's style per `docs/STYLE_GUIDE.md`. Fixed-rate block compression does
not adapt to how simple an image is, so for the flattest textures (skies,
solid-color UI panels, LUTs) a block-compressed format can end up **the same
size or even larger** than a well-optimized Lossless PNG, while for
higher-frequency/noisy textures (surfaces, tiled detail maps) it should still
win. Net expectation: **a real but likely modest APK download-size reduction
(rough order of magnitude: 10-30% of the 41.2 MiB texture budget, concentrated
in the `tiles`/`surfaces` category)**, with the VRAM-memory win being the
stronger, more dependable benefit of the two. This range is an estimate from
published compression-ratio norms, not a measurement — there is no ground
truth until someone actually reimports and re-exports.

## 4. Why no `.import` file was changed this pass

Converting `compress/mode` from 0 to 2 (VRAM Compressed) is mechanically easy
headlessly (edit the `.import` file, re-run `godot --headless --import`) and
was considered for the `tiles`+`surfaces` pilot (65% of the textures/ subtree,
lowest banding risk). Not done, because:

1. **The one check that matters can't run headlessly.** This game's whole
   visual identity is flat, palette-locked, deliberately-banded-free color
   (`docs/STYLE_GUIDE.md` explicitly bans visible banding). Whether a
   specific texture shows banding after ETC2/ASTC compression is a **look at
   it** question — `--headless` has no renderer to look with. Committing an
   unverified blanket conversion risks shipping a visible regression on the
   game's own signature look, with no gate anywhere that would catch it
   (there is no automated banding detector in this repo, static or headless).
2. **`assets/textures/**` is outside this session's reassigned ownership
   zone** for a project-wide pipeline change (only specific new-asset drops
   — e.g. the mobile-art pass's 12 files — were ever reassigned; a bulk
   recompression of everyone else's shipped art is a different kind of
   change).
3. Matches the standing position already recorded in
   `docs/KNOWN_ISSUES.md` ("Mobile texture compression") — this report adds
   fresher, more precise numbers and a prioritized pilot scope, it does not
   reverse that decision.

## 5. Owner remediation (concrete, scoped, in priority order)

1. **Pilot first, not all 738 at once.** In the Godot editor: select
   `assets/textures/tiles/` and `assets/textures/surfaces/` (65% of the
   textures/ subtree, distance-viewed environment tiles — the safest place to
   start) → Import dock → Compress Mode → **VRAM Compressed** → Reimport.
2. **Look at it.** Load a few district scenes (suburbs, industrial — one
   `_lit` and one fog district) in the editor or on-device and check for
   banding on gradients, especially the new LUT-graded skies. This is the
   step no headless session can substitute for.
3. **If clean, expand the same way** to `environment`, `enemies`, `items`,
   `sky`, `fx` (the rest of the "3D/environment" category in §2).
4. **Leave `ui`, `ui_v2`, `touch`, `luts`, `icons`, `onboard_v2`, `crests`,
   `maps` Lossless** — close-viewed 2D art and LUTs (LUTs specifically:
   block compression would corrupt their exact 16-level grading structure).
5. Re-run `bash tools/check.sh --static && tools/qa_sim/headless_suite` after
   any reimport (proves nothing crashed/broke wiring — it cannot prove "no
   banding", that's step 2) and re-measure the real APK size via a signed
   export, updating §1 of this report with actual before/after bytes.
