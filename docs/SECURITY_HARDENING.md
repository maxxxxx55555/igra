# Security hardening (Session 23)

The game is offline and single player: there is no server that can say what is true. Every protection below runs on the device that the player owns, so each
one raises the bar and leaves a trace; none of them is secrecy against the owner of the device, and a determined one can edit the build and the guards with it.
`docs/SECURITY_REREAD_RC16.md` and `docs/CORRECTION_LOG.md` 165 to 198 hold the earlier passes (signed saves, slot binding, schema checks, the exploit group).

## The five items of the directive

| Item | Status | What exists, and why the rest is not built |
|---|---|---|
| SEC1.1 Save encryption (AES-256-GCM) | DEFERRED-HONEST, owner decision | Every save is signed with HMAC-SHA256 (`SaveSystem._sign`), carries a second signature of the progress, keeps three backups and is checked against its schema. Godot's `AESContext` has the ECB and CBC modes only (`refs/godot-docs/classes/class_aescontext.rst`), so GCM is not available to a script; encrypt-then-MAC with CBC and the same HMAC would be. The key would ship inside the game next to the HMAC key, so the file would be hidden from a casual reader and no more: the signature already refuses an edit. The change would also replace the envelope that the attack simulation, the save-integrity gate, the headless suite and the closeout checks read and write by hand. The Secure bar of the directive (signed saves, schema validation, attack_sim 0 fails) holds without it. If the owner wants it: a version 2 envelope behind `SaveSystem.read_signed` and `write_signed`, version 1 still read. |
| SEC1.2 PCK encryption | OWNER | Godot's PCK encryption decrypts only with export templates compiled with the same 256-bit key (`SCRIPT_AES256_ENCRYPTION_KEY` at build time); the official templates of the repository's Godot 4.7 cannot. That needs the engine's source, a toolchain and the Android NDK, and a key kept out of the repository. This session cannot build templates. Recipe: build the Android release templates with the key in the environment, set the key and `encrypt_pck` in the Android preset on the owner's machine only (the preset in the repository keeps its credential fields empty), export. What the preset does hold now: `script_export_mode=2` in the three presets, scripts exported as compressed binary tokens (it was plain binary tokens). The bundle of this project stores the game as an install-time asset pack with a `.gdc` per script (`docs/RELEASE_ARTIFACTS.md`). |
| SEC1.3 Anti-tamper | Built where a script can do it | **Debugger**: on Android, `android.os.Debug.isDebuggerConnected()` through the Java wrapper singleton (the singleton exists in Android builds only, so it is looked up by name); a debugger on a release build is logged, taints the run and ends it. **Emulator**: `OS.get_model_name()` against six marks (`sdk_gphone`, `emulator`, `android sdk built for`, `genymotion`, `ranchu`, `vbox`); logged, not tainting, not halting (many players run the game on one). **File scanner**: the SHA-256 of the text (CRLF as LF) of the 53 content and data JSON files against `data/integrity_manifest.json`, at start (`scripts/security/integrity_scan.gd`; `tools/gen_integrity_manifest.py` writes the manifest and a static gate holds it); a changed, missing or unlisted file is logged and taints the run. **App signature**: NOT built. The Java wrapper calls methods and cannot read fields, and the certificate of an app is `PackageInfo.signatures` or `signingInfo`, both fields; it needs a small Android plugin in Java, and the expected value is the certificate that Play App Signing re-signs the bundle with, known to the owner after the first upload. UNVERIFIABLE-HERE for all of the Android paths (no device). |
| SEC1.4 ProGuard / R8 | N/A with proof | The Java layer of the bundle is the engine's own glue and the AppLovin plugin (removed from the export: 0 dex entries name it). The game's logic and strings are in the asset pack as compressed binary tokens. There is no API key, token or internal URL in the repository to encrypt (`docs/CLEANUP_LEDGER.md`, the secret sweep). Enabling R8 on the engine's classes changes nothing a reader wants hidden and risks a crash on a device nobody here can run. |
| SEC1.5 Anti-cheat | Built | **Speed hack**: two clocks that run in real time, the engine's monotonic ticks and the system's wall clock, are compared over windows of 10 s; a window is off when they differ by more than 25 %; two off windows in a row are a speed hack (one is a clock that was set, or a phone that slept). **Log**: each violation is a line (time, kind, detail) in an AES-256 file through Godot's encrypted `FileAccess`, the last 50 (`scripts/security/security_log.gd`). **Response**: a violation that taints stops the local leaderboard from recording runs (`LocalLeaderboard.record_run`). **Inputs and RPCs**: the damage RPC takes the server's call only and clamps to 0 to 200, the inventory RPCs run on the authority only, the guard clamps health, battery, stamina and coins and restores a position that left the world (`IntegrityGuard`), the economy and the pack are checked by the exploit group (`CLOSEOUT_ONLY=exploit`). |

## Checks

`CLOSEOUT_ONLY=s23` runs SEC1 (the clocks), SEC2 (the log is not readable as text, a tainting flag stops the leaderboard, a clean guard records), SEC3 (the 53
shipped files match their manifest, a changed hash, a missing file and a missing manifest are named, line ends do not matter) and SEC4 (emulator models). The
manifest is checked by the static gate `integrity manifest` of `tools/check.sh`.

## In the bundle

The export filter leaves out `scripts/security/attack_sim.gd` and nothing else of that folder: `integrity_guard.gd` preloads `integrity_scan.gd` and `security_log.gd`, and until Session 23 closed it (CORRECTION_LOG 242) the filter left out the whole folder, so the first bundle of the pass carried a guard that could not load. `tools/qa_sim/export_refs_check.py` holds it in the static gates, and `tools/qa_sim/aab_check.py <bundle>` reads the manifest's files out of an exported bundle and hashes them as the scan does (the fact `integrity`), and asks the pack for every file the shipped files name (the fact `refs`).

## Known limits

The two keys of the game (`SaveSystem._HMAC_KEY`, `SecurityLog.KEY`) are in the scripts: anyone who unpacks the bundle reads them. A repackager who changes a data
file changes the manifest in the same breath. The speed-hack check does not see a hack that moves both clocks. `docs/KNOWN_ISSUES.md` rows 170 and 171 (a daily claim and a hardcore flag outside the signed save) stay accepted limits of an offline game.
