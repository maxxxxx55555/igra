# Передача: состояние проекта и что делать дальше

Документ для следующей сессии и для владельца. Коротко: что сделано,
чему можно верить, а чему — пока нет.

## Что нужно от владельца (всего 4 шага)

1. Влить рабочую ветку `arena/019ffbd0-igra` в `main` (или просто
   `git pull` этой ветки).
2. Выполнить **одну** команду из [`ONE_COMMAND_TEST.md`](ONE_COMMAND_TEST.md).
3. Прислать целиком `tools\autopilot_report\report.txt`.
4. Приложить PNG из `tools\autopilot_report\shots\`.

Играть, проверять руками и отвечать на вопросы не нужно.

## Три уровня доверия к текущему состоянию

Это главное, что стоит понимать про статус проекта.

### 1. Доказано статическими проверками

Прогоняется здесь, в песочнице, командой `./tools/check.sh --static`
(13 гейтов) плюс `flow_check.py` (72 проверки), `scene_node_check.py`,
`orphan_check.py`, `autopilot_api_check.py`.

Гарантируется: синтаксис всех 286 файлов; отсутствие битых `res://`
ссылок и `ext_resource`; совпадение арности сигналов; целостность
сохранений (сохраняется ровно то, что сбрасывается и загружается);
отсутствие TODO/FIXME, BOM, отступов пробелами и закомментированного
кода; каждый скрипт, ставящий игру на паузу, работает во время паузы;
замедление времени не может залипнуть навсегда.

### 2. Будет доказано автопилотом на машине владельца

27 тестов в `tools/autopilot/`, запускаются внутри настоящего Godot.
Именно они закрывают то, что статикой проверить нельзя: реальный старт
автозагрузок, спавн игрока, подбор предметов, укрытия против зрения
монстра, круговорот сохранения, достижимость финала, пауза, смерть,
порядок закрытия по Escape, отсутствие наложений полос HUD, укрытия вне
стен, реакция фонарей на блэкаут.

**Пока не подтверждено ничем:** Godot в этой песочнице недоступен
(все зеркала бинарников закрыты), поэтому сам автопилот ни разу не
запускался. Его вызовы сверены с реальными API статически
(`autopilot_api_check.py`, 55 сверок), но первый живой прогон может
выявить как настоящие баги игры, так и ошибки самого автопилота.

### 3. Требует человеческого взгляда

Ни статика, ни автопилот этого не закроют: читаемость шрифтов,
художественная сочетаемость света и тумана, темп игры, «страшно или
нет», баланс сложности, качество звукового микса.

## Открытые риски

| Риск | Суть |
|------|------|
| Автопилот не запускался | Первый прогон может упасть на мелочи в самом автопилоте, а не в игре. Смотреть на строки `[FAIL]`: если падает `не удалось выполнить`, вероятнее дело в тесте. |
| Скриншоты в режиме `--script` | Godot может не создать окно, и PNG выйдут пустыми. В отчёте это видно как «пустой кадр». Тогда следующей сессии стоит перевести скриншоты на запуск с главной сценой. |
| Нет `.import`/`.uid` в репозитории | При первом открытии будут предупреждения про UID. Лечится одним коммитом после первого импорта — подробности в `KNOWN_ISSUES.md` §1. |
| 105 файлов без ссылок | Заморожены в `tools/orphan_baseline.txt`. Это задел под фичи, а не мусор; удалять их без разбора нельзя (урок `hiding_spot.gd`). |

## Что следующая сессия обязана сделать по отчёту

1. Разобрать каждый `[FAIL]` из `report.txt`. Отличать падение игры от
   падения теста: у теста в тексте будет «не удалось выполнить».
2. Посмотреть скриншоты: если они пустые — чинить способ съёмки, если
   на них видны наложения или пустые экраны — чинить интерфейс.
3. На каждый подтверждённый баг сперва добавлять проверку в
   `flow_check.py` (с мутационным тестом), потом чинить код.
4. После зелёного прогона — ставить тег `v1.0-final`.

## Карта проверок

| Команда | Что делает |
|---------|-----------|
| `./tools/check.sh --static` | все 13 статических гейтов (~1.5 мин) |
| `./tools/check.sh --static --fast` | то же без gdparse (~2 с) |
| `python3 tools/flow_check.py` | 72 проверки игрового цикла |
| `python3 tools/scene_node_check.py` | целостность `.tscn` |
| `python3 tools/orphan_check.py` | файлы без ссылок против baseline |
| `python3 tools/autopilot_api_check.py` | автопилот зовёт только существующие API |
| одна команда из `ONE_COMMAND_TEST.md` | живой прогон игры в Godot |
