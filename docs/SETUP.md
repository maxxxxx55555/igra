# Установка и запуск

## Что нужно

* **Godot 4.7 Stable** — обычная сборка или `_console` (второй печатает
  логи прямо в терминал, что удобно для автопроверки).
* Ничего больше: внешних зависимостей, пакетов и SDK для запуска на ПК
  не требуется.

Для сборки APK дополнительно нужны Android SDK и JDK — см.
[`ANDROID_BUILD.md`](ANDROID_BUILD.md).

## Первый запуск

1. Клонировать репозиторий.
2. Открыть `project.godot` в Godot 4.7.
3. Дождаться импорта ассетов — при первом открытии это занимает время
   (около 156 файлов). Предупреждения про `invalid UID` на этом шаге
   ожидаемы, см. ниже.
4. Нажать **F5**.

Стартовая сцена — `res://scenes/ui/boot_loading.tscn`, она сама
передаёт управление в меню.

## Про предупреждения UID при первом открытии

В репозитории нет файлов `.import` и `.uid` — их создаёт только
редактор. Поэтому первое открытие выдаёт предупреждения вида
`ext_resource, invalid UID: ... - using text path instead`. Игру это не
ломает. Чтобы они исчезли у всех, кто клонирует проект, достаточно один
раз закоммитить сгенерированные файлы:

```bash
git add -A '*.import' '*.uid'
git commit -m "chore: commit Godot import metadata"
```

## Автоматическая проверка игры

Полный прогон игрового цикла внутри настоящего Godot, без ручного
тестирования, — одна команда, описанная в
[`ONE_COMMAND_TEST.md`](ONE_COMMAND_TEST.md).

Результат: `tools/autopilot_report/report.txt` и скриншоты в
`tools/autopilot_report/shots/`. Код возврата равен числу упавших
тестов, поэтому команду можно использовать и в CI.

## Статические проверки (без Godot)

Нужен только Python 3 и, для проверки синтаксиса, `gdtoolkit`:

```bash
pip install "gdtoolkit==4.*"
./tools/check.sh --static          # все гейты, ~1.5 минуты
./tools/check.sh --static --fast   # без gdparse, ~2 секунды
```

Код возврата 0 — всё зелёное. Что именно проверяется, перечислено в
[`HANDOFF.md`](HANDOFF.md).

## Структура проекта

| Папка | Что внутри |
|-------|-----------|
| `scenes/` | сцены: районы, интерфейс, игрок, враги, реквизит |
| `scripts/` | вся логика; `scripts/tools/` — служебные скрипты для редактора |
| `data/` | ресурсы данных: предметы, районы, локализация |
| `tools/` | валидаторы, автопилот, вспомогательные скрипты |
| `docs/` | документация, дизайн-документ, чеклисты |
