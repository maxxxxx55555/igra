# Human checklist — things Claude cannot do

Steps below need a GUI, an account, real credentials, or a build toolchain
this session doesn't have. Everything else (code wiring, config placeholders,
docs) is already done — see `docs/SESSION_REPORT_FINAL.md` for what.

## AppLovin MAX ads

1. **Create an AppLovin account** and app entries (Android) at
   https://dash.applovin.com — get:
   - SDK key
   - Rewarded ad unit ID
   - Interstitial ad unit ID
2. Paste them into `project.godot`'s `[monetization]` section (or via
   Project Settings → search "monetization" in the Godot editor):
   ```
   applovin_sdk_key="<your key>"
   applovin_rewarded_unit_id="<your rewarded unit id>"
   applovin_interstitial_unit_id="<your interstitial unit id>"
   ```
   Leave any of these empty and `ad_service.gd` automatically falls back to
   the debug stub (a visible popup with a countdown) — nothing breaks, ads
   just don't really show. Safe to leave empty for internal testing.
3. **Install the Android Build Template**: Godot editor → Project → Install
   Android Build Template. This is required before `gradle_build/
   use_gradle_build=true` (already set in `export_presets.cfg`) will
   actually work — without it, Android exports will fail.
4. **Verify the plugin is enabled** in the Export dialog: Project → Export →
   Android preset → Plugins tab → confirm "AppLovin Max" is checked. I set
   `gradle_build/plugins_enabled=PackedStringArray("AppLovinMAX")` by hand
   in `export_presets.cfg`, which should be equivalent, but the Godot editor
   GUI is the authoritative way to set this — please double-check it shows
   checked there before trusting the hand-edit.
5. In `android/build/build.gradle` (generated by step 3, doesn't exist
   until you've installed the build template), add:
   ```
   implementation 'com.applovin:applovin-sdk:+'
   ```
   inside the `dependencies { }` block.
6. In `android/build/AndroidManifest.xml` (also generated by step 3), find
   the `.GodotApp` activity entry and change `android:launchMode` from
   `singleInstance` to `singleTask`.
7. Do a real device/emulator test build and confirm:
   - Rewarded ad shows on the death screen's "Watch ad to revive" button
     and on a future battery-boost trigger point (not yet added to any HUD
     button — the reward-consumption code is wired via
     `AdService.reward_granted`, so wiring a new button just needs to call
     `AdService.show_rewarded(&"extra_battery")`, same pattern as the
     revive button in `scripts/death_screen.gd`).
   - Interstitial shows on district travel, respects the 180s cooldown, and
     never shows mid-combat (already implemented, needs real-device
     confirmation).

## Play Store / release

See `docs/release_checklist.md` and `docs/store/play_store.md` for the
already-drafted parts (descriptions, tags, rating notes). Still needs a
human for:
- Google Play Console account + app listing creation.
- Keystore generation for the RELEASE build (a separate one from the debug
  keystore already committed at `res://tls_debug.keystore`):
  ```bash
  keytool -genkey -v -keystore release.keystore -alias tlsrelease -keyalg RSA -keysize 2048 -validity 10000
  ```
  Store this file and its password outside the repo. Paste the path into
  `export_presets.cfg`'s `keystore/release`/`keystore/release_user`/
  `keystore/release_password` before the final signed build.
- Data Safety form + IARC content rating questionnaire in Play Console
  (notes on expected answers already in `docs/store/play_store.md`).
- Privacy policy: needs an actual hosted URL. A short "no data collected"
  policy is accurate for the current build (no accounts, no analytics SDK)
  — just needs to be published somewhere and linked.
- Upload to an internal/closed testing track before production.
