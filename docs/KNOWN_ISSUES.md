# Известные проблемы

Актуально на 2026-08-13. Только то, что проверено по коду; догадки сюда не идут.

## Требует внимания владельца

### 1. В репозитории нет файлов `.import` и `.uid`

**Симптом.** Свежий клон при первом открытии выдаёт предупреждения вида
`ext_resource, invalid UID: uid://... - using text path instead` — по одному
почти на каждый из 156 ассетов.

**Причина.** `.gitignore` содержал правила `*.import` и `*.uid` из эпохи
Godot 3. В Godot 4.1+ официальная рекомендация — игнорировать только
`.godot/` и `*.translation`. Правила из `.gitignore` убраны, но сами файлы
может создать только редактор.

**Что сделать один раз.** Открыть проект в Godot 4.7, дождаться импорта и
закоммитить появившиеся `.import`/`.uid`:

```bash
git add -A '*.import' '*.uid' && git commit -m "chore: commit Godot import metadata"
```

После этого предупреждения исчезнут у всех, кто клонирует репозиторий.

### 2. Проект не проверялся запуском

Godot в рабочем окружении недоступен (зеркала бинарников закрыты), поэтому
живой прогон F5 ни разу не выполнялся. Всё проверено статически:
`./tools/check.sh --static` — 13 гейтов, `flow_check.py` — 72 проверки.

Чтобы это закрыть без ручного тестирования, в проекте есть автопилот:
одна команда из [`ONE_COMMAND_TEST.md`](ONE_COMMAND_TEST.md) прогоняет
22 теста внутри настоящего Godot и складывает отчёт со скриншотами.
**Сам автопилот тоже ни разу не запускался** — его вызовы сверены с API
проекта статически, но первый живой прогон может выявить ошибки и в нём.

Что не закроет ни статика, ни автопилот: читаемость шрифтов, сочетаемость
света и тумана, темп, страх, баланс, качество звукового микса.

## Осознанные ограничения

### 2a. Урок про «мёртвый код»

`scripts/gameplay/hiding_spot.gd` был удалён как файл без ссылок — и это
оказалось ошибкой. Внутри лежала законченная реализация механики из GDD S2.3
(меш, коллизия, занятость, подсказки), полностью совпадающая с
`player_3d.toggle_hiding()`. Ссылок не было ровно потому, что никто не
создавал укрытия в мире, — то есть отсутствовала вторая половина фичи,
а не первая.

Файл восстановлен, `DistrictSceneFactory` теперь расставляет по пять укрытий
на район. **Вывод:** «нет ссылок» означает «надо разобраться», а не
«можно удалять». Именно поэтому остальные 99 файлов заморожены, а не стёрты.

### 3. 99 файлов без ссылок

`python3 tools/orphan_check.py --list` печатает файлы, на которые в проекте
не ссылается ничто: ветки поведения ИИ (`scripts/ai/*`), волновой режим
(`wave_manager.gd`), крафт, лидерборд, 12 сцен секретных комнат и т.д.

Это задел под запланированные фичи, а не мусор: систему обычно пишут раньше,
чем к ней приделывают вызов. Поэтому список заморожен в
`tools/orphan_baseline.txt`, и гейт падает только если он **растёт**.
Удалять их массово не стоит — сначала решить по каждому, нужен ли он.

### 4. Legacy-слой 2D

`scripts/player/player.gd` (CharacterBody2D), `flashlight.gd` (PointLight2D),
`secret.gd`, `puzzle_base.gd`, `examine_object.gd` и сцены `scenes/props/*` —
остатки ранней 2D-версии. Они замкнуты сами на себя: игровая сцена
`main_3d.tscn` использует `player_3d.tscn` и до 2D-кода не доходит.
Вреда не приносят, но при следующей уборке их логично вынести целиком.

### 5. Дубликаты систем, оставленные сознательно

Три пары файлов делают одно и то же, но обе половины живые — удалять нельзя:

| Пара | Кто использует |
|------|----------------|
| `scripts/visual/emissive_windows.gd` | 11 сцен районов (авторские окна) |
| `scripts/world/emissive_windows.gd` | `WorldBootstrap` — для районов без своих окон |
| `scripts/ui/photo_mode.gd` | `UIManager`, по клавише `photo_mode` |
| `scripts/systems/photo_mode.gd` | галерея экранов, с фильтрами |

Раньше обе пары конфликтовали: bootstrap искал узел `Windows`, а сцены
называют его `EmissiveWindows`, поэтому поверх авторских окон строился
второй слой; а оба фоторежима слушали одну и ту же клавишу. Сейчас
конфликты сняты, но при рефакторинге эти пары стоит свести в одну.

### 6. gdtoolkit ложно ругается на многострочные лямбды

`gdparse` версии 4.3.3 не понимает синтаксис многострочных лямбд, который
Godot 4 поддерживает. Три файла дают ложные ошибки разбора:
`loot_drop.gd`, `character_screen.gd`, `screens.gd`.
Код корректен — проверять их нужно самим движком.

## Незакрытые дизайнерские хвосты

Перенесено из `findings.md`, актуальность подтверждена по коду:

- `screens.gd` содержит ~1900 строк с русским текстом в коде вместо `tr()`.
- Адаптивная музыка использует 2 плеера с кроссфейдом, в GDD §25.2 описано
  5 слоёв (сами слои уже грузятся, но ведутся упрощённо).
- APK не собирался: нужны Android SDK и export-шаблоны.
